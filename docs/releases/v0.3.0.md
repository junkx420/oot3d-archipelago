Update both.

## New

- **Shuffle Dungeon Rewards**: off (default), end of dungeons, any dungeon,
  overworld or anywhere. A blue warp, sage or Rauru whose location holds
  something else still shows the game's reward, but Link gets nothing there:
  the location's item comes from the server (and an in-game message names
  it). With the cutscene skips on, the skipped blue warp reports the
  location as before.
- With rewards shuffled, Link may hold a reward without having beaten its
  dungeon, or the other way round. Where the game reacts to a reward, it
  now reacts to the dungeon beaten, as in OoT3D Randomizer: Mido to the Deku
  Tree instead of the Kokiri Emerald; the Kokiri and the Deku Tree Sprout to
  the Forest Temple instead of the Forest Medallion; the Lake Hylia sun to
  the Water Temple instead of the Water Medallion. King Zora ignores Zora's
  Sapphire. Without shuffled rewards the game is unchanged there.
- The Door of Time's stones, Sheik's medallions and the Light Arrow cutscene
  still ask for the rewards themselves, as the logic does.

None of this patches game code.

## Checked

- Host tests for every rule, the apworld's tests (512 passed), seeds of all
  four reward modes generate (also with shuffled songs).
- In a copy of an installed TriAevum the new `TriAevum.exe` matched all 102
  of its game-code checks.

## Known

- Shuffled dungeon rewards were not yet played with a seed. A sage's or
  blue warp's scene shows the game's reward, a song teacher's scene the
  game's song.
- Not supported yet: Master Quest, entrance shuffle, models for other
  games' items. The full list is in `KNOWN_ISSUES.md`.
