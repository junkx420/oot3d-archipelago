# Archipelago integration: architecture

Status: Phase 1 (observation only). Later phases extend this file.

## Module boundary

All Archipelago code lives in `tools/oot3d/archipelago/` and builds as the
static library `triaevum_archipelago`. It depends only on the A32 runtime
interface (`recomp/a32_runtime.h`: `GuestState`, `MemoryBus`) through
`oot3d_native_a32_process`. It includes no window, renderer or UI header.

| File | Responsibility |
| --- | --- |
| `ap_location_key.*` | OoT3D_Randomizer's `(scene, type, flag)` key, pure functions |
| `ap_check_observer.*` | Hook pcs, guest reads at the hooks, check events, address self-check |
| `ap_sha256.*` | SHA-256 for the self-check |
| `addresses.json` | USA→EUR address table with window hashes (generated by `recon/map_rando_addresses.py`) |
| `ap_tests.cpp` | Host tests, no ROM needed |

## Switches

| Switch | Effect |
| --- | --- |
| CMake `TRIAEVUM_ENABLE_ARCHIPELAGO` (default OFF) | OFF: no sources, no definitions. The preprocessed window sources are byte-identical to upstream (checked for all 8 window translation units). |
| `TRIAEVUM_ARCHIPELAGO=1` (environment) | Creates the observer and adds its hook pcs. Unset: no observer, no hooks. |
| `TRIAEVUM_ARCHIPELAGO_LOG=<file>` | Appends check events and the hook report to a file. |
| `TRIAEVUM_ARCHIPELAGO_PROBE=<hex pc>` | Counts an extra function entry (hook experiment only). |

## Hooks (Phase 1)

| Guest function | EUR / exec address | Read | Purpose |
| --- | --- | --- | --- |
| `Actor_OfferGetItem` | `0x003724DC` | r0 actor, r1 play, r2 get-item id; actor id, params, `EnItem00` flag | Remember the latest offer |
| `Item_Give` | `0x00376A78` | r0 play, r1 item; `player->getItemId`, `player->interactRangeActor` | Report a check; match it to the offer, or key songs as delayed locations |

Both are function entries: block starts in every execution mode, so they
need no title-module rebuild (RECON.md section 3). The observer never writes
guest state and never raises an observable exit. It runs before the rest of
the policy, so another hook's exit cannot skip it.

## Self-check

The first hooked block entry of a session compares SHA-256 hashes of the
first 32 bytes of each hooked function with `addresses.json` (compiled into
`kGuestFunctions`; a test keeps both in sync). A mismatch throws
`std::runtime_error` naming the function, so the session stops instead of
observing the wrong code.

## Threading

| Thread | Runs | Touches guest memory |
| --- | --- | --- |
| Guest (window `RunFrame`) | Check observer at its hooks; `Session::Update` after each guest refresh | Yes, reads only |
| Network (`NetworkClient`) | apclientpp: connect, poll, all callbacks | No |
| F1 panel (wherever the settings window draws) | `Session` getters and connect/disconnect/say | No |

The network thread and the game exchange data only through
`NetworkClient`'s command and event queues. `Session` locks a mutex in every
public function, so the panel can draw on any thread.

## Persistence

| File | Content |
| --- | --- |
| `config/archipelago.json` | server, slot name, installation uuid (no password) |
| `savedata/archipelago/<seed>-<team>-<slot>-save<n>.json` | reported location ids, applied item count |
| `resources/archipelago/locations.json` | generated location table (read only) |

The server remains the source of truth for received items; the sidecar
records how many were applied, so a reconnect applies only the rest.

## Location ids

Generated by `recon/generate_tables.py` from OoT3D_Randomizer: id = base
`0x3D0000` + index, append-only by the randomizer's enum name. Each id is
stored with its `(scene, type, flag)` key and a Master Quest flag; a key
maps to one id per dungeon variant.

## apworld

`tools/oot3d/archipelago/apworld/oot3d` is the Ship of Harkinian apworld's
region and rule structure under the game name "Ocarina of Time 3D":

| Part | Role |
| --- | --- |
| `data/locations.json`, `data/items.json` | generated 3D tables (names, ids, vanilla items) |
| `oot3d_data.py` | loads them; `Locations.py` and `Items.py` swap in the 3D ids and drop what the 3DS game lacks |
| `Enums.py` | Ship of Harkinian identifiers with 3D names (`recon/map_soh_names.py --apply`) |
| `location_access/` | regions, events and rules; 3D changes carry a comment naming the OoT3D_Randomizer rule |
| `oot3d_options.py` | the option values the client supports; checked first in `generate_early` |

The logic is checked against OoT3D_Randomizer's own C++ logic by
`recon/compare_logic.py` with the host build in `recon/logic_oracle/`. The
apworld may be stricter than that logic, never more permissive.
